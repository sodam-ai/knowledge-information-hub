## 1. 제품 개요

### 한 줄 요약
소규모 팀이 링크·노트·파일·AI 대화를 한 곳에 모으고, AI로 빠르게 찾을 수 있는 팀 지식 창고.

### 해결하는 문제
팀이 유용한 정보를 발견해도 Slack, 카카오톡, 이메일, 개인 노트에 흩어져 결국 잊혀진다.
"그거 어디 있었지?"를 반복하는 낭비를 없애고, 팀 지식이 사람이 아닌 시스템에 쌓이게 한다.

### 핵심 가치
- **통합 수집**: 링크·텍스트·파일·AI 대화를 유형 구분 없이 하나의 공간에 저장
- **AI 검색**: 키워드가 기억 안 나도 "지난주 AI 관련 저장한 것" 같은 자연어로 찾기
- **팀 단위**: 개인 앱이 아니라 팀이 함께 쌓고 공유하는 공용 창고
- **보안 기반**: 팀 간 데이터 완전 격리, API 남용 방지, 안전한 외부 연동

### 포지셔닝
| 비교 대상 | TeamVault의 차이 |
|-----------|----------------|
| Notion | Notion은 문서 작성 중심. TeamVault는 "저장+찾기"에 특화, 빠름 |
| Raindrop.io | 북마크 전용. TeamVault는 노트·파일·AI 대화까지 통합 |
| Slack 북마크 | 대화 안에 묻힘. TeamVault는 검색 가능한 독립 창고 |

## 2. 사용자

### 주요 사용자
- **누구**: IT·스타트업·크리에이터 계열 소규모 팀 (2~10명)
- **상황**: 업무 중 발견한 아티클, 회의 메모, AI 답변, 공유 파일을 빠르게 저장하고 나중에 꺼내 쓰려 할 때
- **목표**: "이 팀에서 나온 모든 유용한 정보가 한 군데 있다"는 확신

### 사용자 시나리오

**시나리오 1 — 링크 저장 & 팀 검색**
1. 팀원 A가 유용한 AI 기사를 발견하고 TeamVault에 링크로 저장한다
2. 팀원 B가 3일 후 "AI 관련 자료"라고 검색하면
3. A가 저장한 링크 + 태그가 함께 나타난다

**시나리오 2 — 회의 직후 메모 저장**
1. 팀장이 회의 직후 핵심 결론을 텍스트 노트로 저장한다
2. 팀원 전체가 즉시 공유 목록에서 확인한다
3. 궁금한 점을 댓글(Phase 2)로 남긴다

**시나리오 3 — 신규 팀원 온보딩**
1. 새로 합류한 팀원이 초대 링크로 팀에 들어온다
2. 첫 화면에 샘플 콘텐츠 3개가 보이고, 팀 사용법을 자연스럽게 익힌다
3. 지금까지 쌓인 링크·노트를 검색해서 팀 맥락을 빠르게 파악한다
4. 별도 인수인계 없이 3분 만에 팀 지식 기반에 접근한다

**시나리오 4 — 모바일 빠른 저장 (PWA)**
1. 팀원이 모바일 브라우저에서 유용한 기사를 발견한다
2. 공유 버튼 → TeamVault 선택 (Web Share Target API)
3. 앱 없이 즉시 저장 완료

## 4. 사용자 흐름 (User Flow)

### 콘텐츠 저장 흐름
```
앱 열기 → 저장 버튼 → 유형 선택(링크/노트) → 내용 입력 → [태그 추가] → 저장 완료
                                                  ↓
                                         (링크 타입 시) microlink.io로 제목 자동 추출
                                         url_hash 중복 확인 → 중복 시 경고 토스트
```

### 팀 초대 흐름
```
팀 만들기 → 초대 링크 복사(16자 코드, 72시간 유효) → 팀원이 링크 클릭 → 로그인 → 팀 합류
           (rate limit: 합류 시도 시간당 5건/IP) (팀원 20명 초과 시 차단)
```

### 검색 흐름
```
검색창 클릭 → 키워드 입력(최소 2자) → 결과 목록 (제목+내용+태그, pg_trgm+tsvector) → 상세 보기
```

### 모바일 PWA 저장 흐름
```
모바일 브라우저에서 공유 버튼 → TeamVault 선택 (Web Share Target) → 링크 자동 입력 → 저장
```

### 첫 실행 흐름
```
팀 생성 완료 → 샘플 콘텐츠 3개 자동 생성 (링크 1개, 노트 1개, 태그 예시) → 팀원 초대 안내
```

### 계정 탈퇴 흐름
```
설정 → 계정 탈퇴 → 확인 메시지("팀 콘텐츠는 유지됩니다. 개인정보는 즉시 삭제됩니다.")
→ 확인 클릭 → PII 즉시 익명화 + Supabase Auth 삭제 → 탈퇴 완료 (재로그인 불가)
```

### 팀 관리자 변경 흐름 (Admin Succession)
```
[자발적 탈퇴]
팀원(admin)이 팀 나가기 요청
→ 남은 admin이 있는가?
  → 있음: 정상 탈퇴 처리
  → 없음(마지막 admin): "다른 팀원에게 admin 권한 위임 후 탈퇴 가능합니다" 안내 → 차단

[계정 삭제로 인한 자동 승계]
admin 계정 삭제 처리
→ 해당 팀에 다른 admin이 있는가?
  → 있음: 자동 승계 불필요
  → 없음: 해당 팀에서 joined_at이 가장 오래된 member → 자동으로 admin 승격
  → member 없음 (팀원이 본인뿐): 팀 자동 아카이브(비활성 처리)
```

## 5. 보안 요구사항 (핵심 요구사항)

> 보안은 선택 사항이 아닙니다. 아래 항목은 구현 완료 기준에 포함됩니다.

### 필수 보안 항목 (Phase 1 기준)
- **팀 데이터 격리**: Supabase RLS + team_id 필터로 타 팀 데이터 접근 원천 차단
- **API 남용 방지**: Vercel Edge Middleware + Upstash Redis rate limiting (엔드포인트별 제한)
- **SSRF 방지**: 서버에서 외부 URL 직접 fetch 금지 → microlink.io API 위임
- **입력값 검증**: 모든 서버 액션에서 Zod 스키마로 검증 (URL, 태그, 노트 내용 등)
- **초대 코드 보안**: 16자 이상 무작위 코드 + 72시간 만료 + 합류 rate limit
- **비밀 관리**: 서버 키(.env.local)는 서버 액션에서만, 클라이언트 절대 노출 금지
- **콘텐츠 권한**: 수정=본인만, 삭제=본인+admin (RLS 적용)
- **소프트 삭제 보호**: is_deleted 필터 없이 데이터 조회 금지

자세한 보안 설계는 **[04_PROJECT_SPEC.md](./04_PROJECT_SPEC.md)** 의 보안 섹션 참조.

## 6. 성공 기준

### 기술 기준 (동작 확인)
- [ ] 팀원 2명 이상이 가입하고 각자 5개 이상 콘텐츠를 저장할 수 있다
- [ ] 검색 응답 p95 < 2초 (클라이언트 렌더 완료 기준, Vercel Analytics 측정)
- [ ] 아이템 목록 로딩 p95 < 1초 (첫 20개 기준)
- [ ] 링크 저장 (microlink.io 포함) p95 < 3초
- [ ] 링크·노트 저장이 모두 오류 없이 동작한다
- [ ] microlink.io로 링크 제목이 자동 추출된다
- [ ] 한국어 키워드로 검색 시 관련 콘텐츠가 상위 노출된다 (pg_trgm + tsvector)
- [ ] 모바일 브라우저에서도 저장·검색이 가능하다
- [ ] PWA 홈 화면 추가 + Web Share Target이 동작한다
- [ ] 팀원 초대 → 합류 → 공유 항목 조회가 1분 안에 완료된다
- [ ] Rate limiting이 동작한다 (초과 시 429 응답 + 친절한 메시지)
- [ ] 팀원 20명 초과 합류 시도가 차단된다
- [ ] 다른 팀 데이터가 조회되지 않는다 (RLS 검증)
- [ ] 계정 탈퇴 후 해당 이메일로 재로그인이 불가하고, 이름이 익명화된다

### 사용 기준 (실제 가치 확인, Phase 1 배포 후 2주 내)
- [ ] 팀이 별도 도구(Slack/카카오톡) 없이 TeamVault에 먼저 저장하기 시작한다
- [ ] 팀당 콘텐츠 20개 이상 자발적으로 쌓인다
- [ ] "저장한 거 어디 있어?"라는 질문이 줄었다는 팀원 피드백을 받는다
- [ ] 팀원 중 한 명이 "나 혼자 써도 편하다"고 말한다 (개인 사용성 검증)

| 리스크 | 가능성 | 영향 | 대응 방향 |
|--------|--------|------|-----------|
| 팀이 사용하지 않음 ("저장하기 귀찮다") | 높음 | 높음 | PWA Web Share Target으로 모바일 저장 1탭으로 단축 |
| 한국어 검색 품질 저하 | 중간 | 높음 | pg_trgm + tsvector 병행 (Phase 1), pgvector (Phase 2) |
| 콘텐츠 너무 많아지면 검색 품질 저하 | 중간 | 중간 | Phase 2에서 AI 검색 도입 |
| Supabase 무료 티어 한계 초과 | 낮음 | 중간 | 팀원 20명 + 팀 5개 하드 리밋, 건당 20MB, 팀 1GB |
| 초대 링크 유출로 외부인 팀 합류 | 낮음 | 높음 | 16자 코드 + 72시간 만료 + 합류 rate limit (5건/시간) |
| 악성 파일 업로드 (Phase 1.5~) | 낮음 | 높음 | magic bytes 검증 + private 버킷 + 다운로드 전용 |
| API 비용 폭발 (AI 기능 남용) | 중간 | 높음 | Rate limiting (AI 엔드포인트 더 엄격) + 팀당 한도 |
| SSRF 공격 (악의적 URL 입력) | 낮음 | 높음 | microlink.io 위임 + 내부 IP 차단 |
| 서비스 키 클라이언트 노출 | 낮음 | 치명 | 서버 액션 분리, service role key 배치 전용 |
| PII 장기 보관 (개인정보 침해) | 낮음 | 치명 | 탈퇴 즉시 익명화 (법적 요구사항) |
| 탈퇴 계정 재가입 후 데이터 연결 | 매우 낮음 | 높음 | 익명화 email 형식으로 재가입 시 연결 차단 |
| 리소스 남용 (팀 대량 생성) | 낮음 | 중간 | 팀 생성 5개/사용자 하드 리밋 |
